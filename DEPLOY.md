# Deploying ScreenIQ (free tiers)

```
Browser ──► Vercel (Next.js)  ──/api/*──►  Render web service (FastAPI + ARQ worker)
                                              ├── Render Key Value (Redis queue)
                                              ├── Neon (Postgres + pgvector)
                                              ├── Cloudflare R2 (resume files)
                                              └── Gemini API (free tier)
```

Why it's shaped like this:

- **One Render service runs both the API and the worker** (`backend/start.sh`): Render has
  no free background workers.
- **Vercel proxies `/api/*` to Render** (`frontend/next.config.ts`): the browser sees one
  domain, so the httpOnly refresh cookie is first-party. Calling Render directly from a
  `vercel.app` page would break "stay logged in".
- **Render Key Value instead of Upstash**: the worker polls Redis about twice a second,
  which would use up Upstash's free monthly command quota in days.

Time needed: about 30 minutes. Do the steps in order; each one gives you a value the next
step needs. Never paste secrets into chat or commit them; they go only into the
Render/Vercel dashboards.

---

## 1. Neon (database)

1. Sign up at <https://neon.tech> and create a project: name `screeniq`, Postgres 16+,
   region **Asia Pacific (Singapore)**.
2. On the dashboard, open **Connect**. Turn **Connection pooling OFF** (our async driver
   needs a direct connection), and copy the connection string. It looks like
   `postgresql://neondb_owner:...@ep-xxx.ap-southeast-1.aws.neon.tech/neondb?sslmode=require`
   - the app converts it to the async driver's format automatically.

pgvector and citext are enabled by our first migration; Neon supports both.

## 2. Cloudflare R2 (resume files)

1. Sign up at <https://dash.cloudflare.com>, open **R2 Object Storage**, and create a
   bucket named `screeniq-resumes`. Cloudflare asks for a payment method to activate R2,
   but the free tier (10 GB, no egress fees) costs nothing.
2. **R2 → Manage API tokens → Create API token**: permission **Object Read & Write**,
   scoped to the `screeniq-resumes` bucket. Copy the **Access Key ID**, the **Secret
   Access Key**, and the **S3 endpoint** (`https://<account-id>.r2.cloudflarestorage.com`).

No CORS setup is needed: the app only *opens* files through short-lived signed links.

> No card? Supabase Storage also speaks the S3 API on its free tier. Use its S3 endpoint
> and keys instead, and set `S3_REGION` to your Supabase project's region.

## 3. Render (API + worker + Redis)

1. Sign up at <https://render.com> with GitHub.
2. **New → Blueprint**, pick the `ScreenIQ` repository. Render reads `render.yaml` and
   shows two resources: `screeniq-api` (web service) and `screeniq-queue` (Key Value).
3. Fill in the secrets it asks for:

   | Variable | Value |
   |---|---|
   | `DATABASE_URL` | Neon connection string (step 1) |
   | `GEMINI_API_KEY` | your Google AI Studio key |
   | `S3_ENDPOINT` | R2 S3 endpoint (step 2) |
   | `S3_ACCESS_KEY` / `S3_SECRET_KEY` | R2 token keys (step 2) |
   | `CORS_ORIGINS` | leave as `https://example.com` for now; fixed in step 5 |

   `JWT_SECRET` is generated by Render; `REDIS_URL` is wired to the Key Value automatically.
4. **Apply**. The first build takes a few minutes. When it's live, open
   `https://screeniq-api.onrender.com/ready` (your URL may have a suffix): you should see
   `{"status":"ready","checks":{"database":true,"redis":true}}`.

Free instances sleep after 15 minutes without traffic; the first request afterwards takes
about a minute while it wakes up. Queued parsing/screening jobs wait safely in Redis.

## 4. Vercel (frontend)

1. Sign up at <https://vercel.com> with GitHub. **Add New → Project**, import `ScreenIQ`.
2. Set **Root Directory** to `frontend` (framework: Next.js is detected).
3. Environment variables (all environments):

   | Variable | Value |
   |---|---|
   | `API_ORIGIN` | your Render URL, e.g. `https://screeniq-api.onrender.com` (no trailing slash) |
   | `NEXT_PUBLIC_API_URL` | `/api/v1` |
   | `NEXT_PUBLIC_DEMO_MODE` | `true` (shows the "upload fictional resumes only" notice) |

4. **Deploy**. Note the URL, e.g. `https://screeniq-xyz.vercel.app`.

## 5. Finish up

1. In Render, set `CORS_ORIGINS` to your Vercel URL and save (it redeploys).
2. Smoke test, on the Vercel URL:
   - Home page shows the green "API ok" dot (proves the `/api` proxy works).
   - Sign up → create a job → **Draft with AI** → save the rubric.
   - Upload one or two **fictional** resumes → watch them parse and get screened.
   - Reload the page: you stay logged in (proves the refresh cookie works).

## Updating

Push to `main`: Render and Vercel both redeploy automatically. Database migrations run
on every Render start (`alembic upgrade head` in `start.sh`).

## Troubleshooting

| Symptom | Likely cause |
|---|---|
| Render logs: `JWT_SECRET must be set` | `APP_ENV=production` refuses a weak secret; keep Render's generated one. |
| `/ready` shows `"database": false` | Pooled Neon URL, or missing `?sslmode=require`. Use the direct string. |
| Uploads fail with "upstream error" | R2 keys/endpoint wrong, or the token isn't scoped to `screeniq-resumes`. |
| Logged out after every reload | `NEXT_PUBLIC_API_URL` isn't `/api/v1`, so the browser calls Render directly. |
| Everything is slow at first | The free Render instance was asleep; wait ~1 minute. |
| Resumes stuck on "queued" | The instance went to sleep mid-batch; open any page to wake it. |

**Privacy:** the free Gemini tier may use prompts to improve Google's products, and prompts
contain resume text. Keep the public demo to fictional resumes, and switch the key to the
paid tier before using real candidates' data (ADR 0003).
